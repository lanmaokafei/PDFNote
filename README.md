# PDFNote

本地优先、卡片轴心的 PDF 学习应用：在 PDF 上框选摘录即生成卡片，同一张卡片同时作为脑图节点和 FSRS 闪卡使用。

技术栈：Tauri v2 + React 19 + TypeScript + Vite + SQLite + PDF.js + ts-fsrs + React Flow。

## 已实现

- **本地资料库**：PDF 选择导入、SHA-256 去重、应用数据目录副本、断链检测、哈希一致性校验、重新定位、删除时保留或级联删除卡片。
- **同屏工作台**：左 PDF、右脑图，顶部悬浮分段栏，底部工具坞；分栏可拖动，脑图可一键收起。
- **PDF 工作区**：PDF.js 连续滚动与页级虚拟化、256KB Range 分块读取、缩放、页码跳转、自动回到上次阅读页、高亮/矩形框选建卡、文字层提取、Apple Vision OCR、标注拖拽、标注删除语义选择、文档遮挡主动回忆。
- **可选文字层（0.9.0）**：切到「文字」工具后可像 Word 一样在页面上随手拖选文字，选中即复制或直接建卡。页面打开时后台整页识别一次（有 PDF 文字层则用精确字形坐标，扫描页用 Apple Vision 行级 OCR），结果带每行坐标并缓存到 SQLite，之后所有点选/框选零延迟。详见 [Apple Vision OCR](docs/ocr.md)。
- **元素右键菜单（0.10.0）**：接管 WKWebView 只有 Reload 的原生右键菜单。选中文字可复制/引用/建卡，标注可加标签、链接、合并、删除，墨迹可单条删除，页面空白处可切工具、缩放、翻页、复制本页文字；脑图节点、资料库文档、复习卡片与全局空白区也都有对应操作。详见 [应用内右键菜单](docs/context-menu.md)。
- **连续尺寸滑杆（0.37.0）**：墨迹小菜单上的「笔宽」和「橡皮半径」不再是几个档位按钮，改成一个**浮在菜单上方的拖拉控件**——两端标着「细 / 粗」「小 / 特大」，拖动时数值与圆点预览实时变化。笔宽 `0.0018–0.0072`，橡皮半径 `8–56px`（最小就是原来的「小」，最大就是「特大」），滑杆值就是橡皮圆圈的半径；笔记本 dock 用同一个组件，范围与手感完全一致，两个工作区还共享一份尺寸偏好。详见 [墨迹与尺寸滑杆](docs/card-features.md)。
- **手写笔记本与图层（0.36.0）**：独立于任何书页的无限纸张手写本。新建时选纸样（横线 / 网格 / 点阵 / 空白），写到手底自动加纸（上限 60 页）；每本自带「图层 1」，可继续加图层分轮演草——眼睛切显示、锁切可写、双击改名、删除需确认。schema v10 新增 `notebooks / layers / notebook_inks`，`layers` 预留 canvas / mindmap 两种 scope，供后续画布涂鸦与脑图分层复用。详见 [手写笔记本与图层](docs/notebooks.md)。
- **可编辑结构大纲（0.35.0）**：大纲不再只是只读投影。点标题直接改（改的就是行里显示的字段），回车建同级、⌘/Ctrl+回车建子级、Tab / Shift+Tab 缩进提升、拖到另一行的上/中/下三段分别插到前面/变成子级/插到后面。所有改动经新增的 `apply_card_order` 单事务批量落库（逐条防环、失败整批回滚），画布与大纲立刻一致。详见 [可编辑结构大纲](docs/outline-editing.md)。
- **卡片盒看板（0.34.0）**：散在各本书、各张脑图里的卡片汇到一个看板，按**标签 / 书目 / 复习状态**横向分栏，可再叠一层二级分组（书目→标签、标签→书目）。支持关键词、书目、标签、状态与「只看待复习」组合过滤；按标签分组时把卡片拖到另一列即可改标签（来源标签自动移除，拖回「未分组」会被拒绝）。点卡片回到原文页，没有原文的知识卡直接进脑图。每列按 40 张分页渲染，上千张卡也不会一次挂满 DOM。见 [卡片盒看板](docs/card-box.md)。
- **文档回忆藏手写（0.34.0）**：进入「文档回忆」时，除了原有遮挡块，手写墨迹与页边留白也一起隐藏——先回忆自己的笔迹和旁注，再逐块揭示；退出后立即恢复。
- **画布样式设置（0.33.0）**：卡片样式面板新增第 6 套主题「色块」——实色主色标题栏 + 自动对比字色、去掉左侧色条、深墨圆角连线带端点圆点、关联链接跟随色调且不标「链接」，一键接近 MarginNote 式画布。单项可调：标题栏（淡底 / 实心 / 纯白）、连线（发丝 / 深墨 / 子树色）、边框（常规 / 发丝 / 无边框）、关联链接颜色与标签开关；老主题默认观感不变。详见 [脑图卡片样式](docs/mindmap-card-style.md)。
- **体验修正（0.32.2）**：点「立即升级」打开安装器后应用**自动退出**（2 秒），否则运行中的 PDFNote.app 会被 Finder 判定「正在使用中」、拖不进 Applications；升级成功后的下次启动自动删除已装版本的安装包（`updates/` 不再越积越大，比当前版本更新的包保留）。
- **体验修正（0.32.1）**：三处小修——设置「检查更新」按钮补齐尺寸规格（与其他按钮一致）；连接测试命中模型后也显示「可用模型」列表（原先只在警告分支显示）；脑图微缩导航图色块跟随二十四节气色调（原先一片灰绿）。详见 [脑图卡片配色](docs/mindmap-tone.md)。
- **在线检测升级（0.32.0）**：启动后自动检查 GitHub Releases 是否有新安装包，有则弹窗提示升级；点「下载升级」显示实时进度（百分比 + 字节），下载完成自动校验 SHA-256，再点「立即升级」打开 DMG 安装器并**自动退出应用**以便覆盖安装；升级后安装包自动清理。「稍后」记住该版本不再自动弹；设置里可随时手动检查并查看当前版本。网络请求全在 Rust 侧，浏览器预览模式明确报错。详见 [软件更新](docs/update.md)。
- **墨迹橡皮可调大小（0.31.0，0.37.0 改为连续滑杆）**：橡皮不再是「必须正好点在笔画上」。选中橡皮后可用浮动滑杆调整半径，鼠标位置显示红色虚线圆圈，圆圈半径就是命中范围；碰到的笔迹高亮变红，**按住拖动可以连擦**，松手统一删除。命中距离 = 橡皮半径 + 线宽一半，拖大半径就能轻松选中要清理的笔迹，圈外的笔迹不受影响。
- **卡片配色进样式面板（0.30.0）**：二十四节气色板原本只能靠点卡片左上角的 Q 徽标一格一格循环，很难发现也不好精确选择。现在「卡片样式」面板顶部就是完整的 24 色板（每块带节气名·色名 tooltip），点色块直接改这张卡的颜色，「跟随子树」清掉指定回到自动分配。两条路写的是同一份数据。
- **卡片样式：主题与自定义（0.29.0）**：卡片 / 大纲行**右键 → 外观 → 卡片样式…**，可以一键换掉整张画布的视觉，也可以单项微调。5 套主题：宣纸（默认）、极简（无边框发丝线）、线框（深描边直角）、淡彩（整卡吃节气淡底）、墨色（深色卡面）。自定义三项：卡面（纸白 / 淡彩 / 墨色）、圆角（直角 / 小圆 / 大圆）、密度（紧凑 / 标准 / 宽松）。改动即时生效，按画布保存在本地。样式与二十四节气色正交：换主题不动颜色，换颜色不动样式。详见 [脑图卡片样式](docs/mindmap-card-style.md)。
- **AI 解析覆盖所有卡片（0.28.0）**：以前只有填了 Q 的卡片才有「AI 解析」，PDF 划重点建的卡（只有摘录）整条入口被条件渲染滤掉。现在每张有内容的卡片都带这个按钮，解析对象按「问题 → 摘录 → 笔记」取第一个非空项；没有 Q 的卡以摘录为主题，提示文案也跟着改。只有三者全空的纯结构节点（Anki 牌组行）保持禁用并说明原因。
- **脑图卡片配色（0.27.0）**：卡片不再是清一色白底灰绿。每个卡片按「所属子树的根」稳定分配一个**二十四节气传统色**（24 色，取自《中国传统色》96 色），同一簇同色 → 铺开时自然形成彩色簇群。白底保证长文可读，颜色只出现在左侧 3px 色条、标题栏淡底、Q 徽标与页码 chip 上；淡底与深色字由主色自动派生，对比度强制 ≥ 4.5:1。点 Q 徽标可循环换色，偏好存在本地。缩到低倍时节点虽降级为标题条，颜色仍然保留——这个比例下颜色是唯一的辨认依据。详见 [脑图卡片配色](docs/mindmap-tone.md)。
- **PDF 文字层按 run 对齐（0.26.0）**：有真实文字层的 PDF 不再用「行高 × 0.86」估算字号、整行拉伸，而是按 PDF 的每个文本 run 渲染：字号取自 `transform`、基线取自文字项 y、横向按 run 字宽缩放。大字号、行内混排、字距被调整过的书，选区色块都能压住字形。只有页码、且页面确实是扫描图的页会回退整页 OCR。详见 [Apple Vision OCR 与可选文字层](docs/ocr.md)。
- **每本书自带画布（0.25.0）**：导入 PDF 时就在同一事务里建一张以书名为名的脑图画布；打开时优先用你上次选的画布，其次用这本书最新的画布，都没有（升级前导入的老书）就自动补建一张，不再回落到全局画布看到上一本书的 AI 拆书内容。手动切到任意画布都会被记住，下次打开自动关联。详见 [多画布脑图与 AnkiDroid 导入](docs/mindmap-canvases.md)。
- **新卡落在视口中心（0.24.0）**：在 PDF 上划重点或在脑图里新建卡片，落点改成右栏画布**当前视口中心**，不再固定出现在原点 / 左下角。连续建卡按 3×3 环错开 36px，切画布会重置；旧版本留下的 `(0,0)` 占位卡也会在下次刷新时被带到视口中心。坐标随 `create_card` 的 `x`/`y` 一次写入 `mindmap_layout`。详见 [脑图布局](docs/mindmap-layout.md)。
- **低缩放拖拽卡顿修复（0.23.0）**：把 1483 张卡的画布缩到 15% 后连续拖卡片不再卡死。根因是 React Flow 在节点拖拽时会为视口内每个节点逐帧重建——338 个节点同屏时，一次拖拽放大成 7,887 次重渲染、1,104 次重挂载、6 个长任务。现在低缩放（<45%）节点只画标题条、不画边、不写回尺寸，拖拽让给画布平移；交互期间暂停尺寸回写，节点对象复用、context 稳定、KaTeX 缓存改 LRU。实测最长单帧 247ms → 47ms，长任务 6 个 → 0。详见 [大画布性能](docs/mindmap-performance.md)。
- **大画布性能（0.22.0）**：1483 张卡的画布从「8.4 秒才看到第一个节点、3.3 万 DOM、215MB 堆」降到 **0.9 秒、474 个 DOM、60MB**。做法是视口裁剪（只挂载屏幕内的节点）、把每个节点 O(n) 算子节点的逻辑改成一张预算表、只在缺坐标时才重排、大图不做无意义的全量 fitView、大纲按 200 行追加、400 节点以上关掉 MiniMap。详见 [大画布性能](docs/mindmap-performance.md)。
- **主动回忆输入与答案对比反馈（0.21.0）**：复习卡正面那句静态提示换成答案输入框，先写出来再揭示背面；系统把输入与原文摘录 / 个人笔记做本地文本对比，给出匹配度、一句话评价以及「已写到 / 待补上」的要点词。揭示前不泄露答案，评分仍由你自评，输入不落库。支持 `⌘/Ctrl + Enter`。详见 [主动回忆输入与答案对比反馈](docs/review-answer-feedback.md)。
- **多画布脑图与 AnkiDroid 导入（0.20.0）**：同一本书可以建多张脑图，也可以建不绑定书的全局画布；每张画布的卡片与坐标互相隔离，选择偏好按书记住。支持导入 AnkiDroid 导出的 txt（标准 6 列 / 仅正面两种格式），牌组 `::` 层级变成脑图分组，正面 / 背面变成问题卡与摘录，可按牌组勾选、按画布去重并自动整理。详见 [多画布脑图与 AnkiDroid 导入](docs/mindmap-canvases.md)。
- **卡片笔记完整阅读（0.19.0）**：脑图卡片与大纲行的摘录 / 笔记不再被写死截断。长文本默认折叠成几行并标「展开 ⌄」，点标题或正文即展开；内容太长时卡片内出现滚动条，滚轮只滚文字、不平移画布。AI 解析写回笔记后会自动展开，大纲行也能看到笔记。
- **可设拆分层级（0.18.0）**：AI 拆书向导新增「拆分层级」，默认 2 层、可选 1–5 层；选 4 层就能把「章 → 小节 → 名词 → 解释」一次拆出来，阶段一多抽名词定义、阶段二按层生成骨架，设置会记住。详见 [AI 拆书](docs/ai-book-digest.md)。
- **脑图自动整理与清空卡片（0.17.0）**：多张独立卡片不再堆成细长竖条，而是打包成紧凑网格并在整理后自动对齐视口；工具栏新增「清空卡片」，可选择「仅清空脑图」或「彻底删除」。详见 [脑图自动整理与清空卡片](docs/mindmap-layout.md)。
- **拆书卡片回跳与 AI 解析（0.16.0）**：拆书生成的卡片带 `P3` 来源页码标签，点一下左侧 PDF 自动跳到对应页；带 Q 的卡片可直接「AI 解析」，模型按「是什么 / 为什么 / 怎么用 / 易错点」写回笔记。分组节点无页码时自动继承子节点页码。
- **AI 拆书（0.15.0）**：一键把论文 / 教材拆成问题驱动的脑图骨架。分块抽笔记 → 汇总层级 → 写入卡片，每个节点带原文摘录与页码；四种姿态：结构（背景/方法/结果/讨论）、智能词典（术语喂标题链接）、英文生词（CEFR 分级）、题目（自测问题）。100 页以上可中断续跑。详见 [AI 拆书](docs/ai-book-digest.md)。
- **留白（0.14.0）**：页面空白处右键即可在页边贴一张独立草稿，不绑定任何文字；失焦自动保存，可折叠成边缘小圆点或删除。适合记录「这一段暂时用不上、但以后可能有用」的想法。详见 [留白：页边草稿](docs/page-notes.md)。
- **公式渲染（0.13.0）**：卡片摘录里的 LaTeX 会在脑图节点、大纲、复习卡背面直接排版显示；裸 LaTeX（AI 识别的常见输出）也能自动识别，混排文本里的 `$...$` 同样生效。渲染完全本地（离线 KaTeX），原始 LaTeX 始终保留可编辑。详见 [公式渲染](docs/math-rendering.md)。
- **可选 AI 识别（0.12.0）**：顶栏齿轮里可配置 OpenAI 兼容的视觉模型（本机 Ollama / LM Studio 或自填云端 Key）。配置后，扫描页的**公式选区**自动转成 LaTeX 写入卡片摘录，原图仍保留对照；未配置时应用完全不联网，公式照旧「原图 + 手动补录」。详见 [可选 AI 识别](docs/ai-recognition.md)。
- **标题链接（0.11.0）**：卡片标题与别名自动注册为关键词，读到任意文档时页面中命中的词会高亮，点击即可回看当年那张卡的摘录、笔记与来源。纯本地 Aho-Corasick 字典匹配，不走 AI、不联网；默认关闭，卡片库积累后开启。详见 [标题链接](docs/title-link.md)。
- **Apple Vision OCR**：macOS 原生单引擎（`VNRecognizeTextRequest` accurate / revision 3 / 自动语言检测），不打包离线模型；扫描页无文字层时自动识别选区并建卡，公式与图表保留选区原图。详见 [Apple Vision OCR](docs/ocr.md)。
- **知识脑图**：React Flow 自定义卡片节点、折叠/展开、拖拽改父级、连线改父级、防环、多选、布局持久化、独立建卡、卡片编辑、脑图逐级主动回忆。
- **FSRS 复习**：ts-fsrs 四档评分、到期队列、立即持久化、幂等事件、复习审计、每日统计、14 日趋势、正反面内容编辑。
- **备份与恢复**：ZIP 完整备份、manifest + SQLite 一致性快照 + PDF 副本、哈希与 schema 校验、merge/overwrite 导入、自动备份保留 5 份、防 zip slip。
- **本地优先**：无账号、无云同步；除「软件更新」检查 GitHub Releases（自动检查失败静默、手动检查可见）与可选 AI 识别外，业务功能不发起网络请求。最小 Tauri 权限，前端不直接执行 SQL。

## 运行

```bash
npm install
npm run tauri dev
```

浏览器 UI 预览（无数据库与导入能力）：

```bash
npm run dev                      # 默认 http://localhost:1420
npm run dev -- --host 127.0.0.1  # 跑冒烟脚本时用这个（脚本访问 127.0.0.1）
```

原生依赖：Rust stable、Node.js 20+、macOS 上的 Tauri 系统依赖（应用仅在 macOS 运行）。

> 构建注意：`public/` 会被整体复制进 `dist` 并嵌入 `.app`。测试用大文件请放在 `test-fixtures/`（已被 `*.pdf` 忽略），不要放进 `public/`；`vite.config.ts` 的 `emptyOutDir: true` 会清理历史构建产物。发布前确认 `dist` 只含 `pdfjs/` 与当前 assets，避免包体积膨胀。

## 关键设计

- Card 是唯一知识原子。PDF 高亮、脑图节点、复习闪卡只是同一 Card 的 projection。
- 内容与语义树在 `cards`，标注几何在 `annotations`，自由布局在 `mindmap_layout`，画布归属在 `mindmap_canvases`，评分审计在 `review_logs`。`(canvas_id, card_id)` 决定卡片出现在哪张画布，`surface_mindmap` 只是派生开关。
- 所有 SQL 在 Rust 侧执行；建卡、脑图移动、评分、文档删除和备份导入均使用显式事务。
- 评分采用 `expected_updated_at` 乐观锁 + `client_event_id` 唯一约束，避免重复计分与并发覆盖。
- PDF 副本按内容哈希命名，备份恢复前后校验每个 PDF 的 SHA-256。

DMG 内已放置 **Applications 快捷方式**：打开镜像后把 PDFNote 拖进「应用程序」即可完成安装（打包时用 staging 目录 + `ln -s /Applications`，再 `hdiutil create -srcfolder`）。

### 发布到 GitHub

发布固定为四步闭环：**构建签名 → 打包并校验 DMG → 提交推送 git → 同步到 GitHub Release**。

```bash
npm run build && npx tauri build --bundles app
# hdiutil 打包（staging + ln -s /Applications）→ hdiutil verify → shasum -a 256 > release/...dmg.sha256
git add -A && git commit -m "..." && git push origin main
npm run release:github        # 上传 DMG 与 .sha256 到 https://github.com/lanmaokafei/PDFNote/releases
```

`release/` 被 `.gitignore` 忽略，DMG 不进仓库。`scripts/publish-github-release.mjs` 上传前会校验 `.sha256` 与 `hdiutil verify`；同名同内容资产跳过，内容不同时必须显式加 `--replace` 才会删除旧资产重传；tag 与当前 HEAD 不一致会警告。需要 `GITHUB_TOKEN` / `GH_TOKEN`（或已登录的 gh CLI、`~/.config/pdfnote/github-token`），token 需 Contents: write 权限。发布后务必下载线上 DMG 比对 SHA-256，避免网页手动上传的未签名构建与本地签名版混淆。

打包完成后记得取消注册构建目录里的副本，否则它会和 `/Applications` 抢 LaunchServices 的“主副本”，表现为启动台 / 应用程序面板里看不到图标：

```bash
LSREG=/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister
$LSREG -u src-tauri/target/release/bundle/macos/PDFNote.app
$LSREG -f /Applications/PDFNote.app
killall Dock
```

安装后如遇以下情况：

- **启动台 / 应用程序面板里看不到图标**（Spotlight 能搜到、也能打开）：说明 LaunchServices 里登记了多个同 bundle id 的副本（构建产物、已卸载的 DMG 卷），系统把“主副本”指到了不存在或开发目录的路径。按顺序执行：

```bash
LSREG=/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister
$LSREG -dump | grep "PDFNote.app"          # 看有哪些残留路径
$LSREG -u "/Volumes/PDFNote/PDFNote.app"   # 逐个取消（换成上面列出的路径）
$LSREG -u src-tauri/target/release/bundle/macos/PDFNote.app
$LSREG -f /Applications/PDFNote.app        # 安装副本重新登记
killall Dock
```

  之后 `lsregister -dump | grep PDFNote.app` 应只剩 `/Applications/PDFNote.app`，`open -a PDFNote` 会启动安装版。

- **首次打开提示“无法验证开发者”**：这是未做 Apple 公证的正常结果。在「应用程序」里右键 PDFNote → 打开，或到「系统设置 → 隐私与安全性」点“仍要打开”。
- **已经装了旧版本**（0.12.2 及更早）导致 Launchpad 异常：旧包是链接器自动签名，bundle 资源未封印。用新版覆盖，或手动修复已安装副本：

```bash
codesign --force --deep --sign - --identifier com.pdfnote.local /Applications/PDFNote.app
xattr -dr com.apple.quarantine /Applications/PDFNote.app
killall Dock
```

## 重要修复

- 0.31.0 改进**墨迹橡皮选不中细笔迹**：以前橡皮没有大小概念，只能精确点中线条本身。现在可调大小（8/18/32/56px），带红色虚线光标圆圈显示命中范围，悬停高亮将被擦掉的笔迹，按住拖动可连擦；命中 = 橡皮半径 + 线宽一半。

- 0.30.0 补上**样式面板里的二十四节气色板**：配色此前只在卡片 Q 徽标上循环，入口很深、不好精确选择。现在右键 → 卡片样式，面板顶部直接点色块换色，「跟随子树」可清除手动指定。

- 0.29.0 解决**卡片换不了样式**：样式此前是写死的一套。现在右键卡片即可打开样式面板，5 套主题一键替换整张画布，卡面 / 圆角 / 密度可单项覆盖，换主题会清掉覆盖回到整套预设。样式只挂在工作区根节点的 4 个 data 属性上，节点只继承 CSS 变量，1483 节点下不增加渲染成本。

- 0.28.0 修复**部分脑图卡片没有 AI 功能**：卡片底部原来是 `card.question.trim() && (...)` 条件渲染，PDF 划重点建的卡（`question: ''`、只有摘录）不显示按钮；后端 `explain_card` 也会以「没有填写问题」直接拒绝。现在前后端统一按「问题 → 摘录 → 笔记」取解析对象，只有纯结构节点禁用。

- 0.27.0 解决**脑图卡片颜色单调**：全画布原本只有一套灰绿色。现在按子树根分配二十四节气色，一簇一色；颜色只出现在标记位（色条 / 标题淡底 / 徽标 / 页码），卡身保持纯白。缩放到低倍时 lite 节点仍保留色调，仍是彩色网格而不是一片灰。

- 0.26.0 修复**PDF 文字层选区错位**：大字号页面上选区色块浮在文字上方、只覆盖半行。根因是字号按行高估算、行顶部按「基线 + 行高」折算、整行一个 `scaleX`。现在按 PDF 的每个文本 run 定位（真实字号、基线、字宽），扫描页仍走 Vision 行盒；只有页码的扫描页才回退整页 OCR。

- 0.25.0 修复**打开新 PDF 却看到上一本书的脑图**：导入时不再只建文档，而是同事务建一张绑定该书的画布；打开时按「上次选择 → 本书最新画布 → 补建 → 全局」的顺序选，不再默认落到 `main`（那里通常是上一本书的 AI 拆书内容）。画布归属解析完成前不加载卡片，避免短暂闪出全局画布。

- 0.24.0 修复**新卡固定生成在画布原点**：PDF 划重点建卡时坐标写到 `(0,0)`，脑图又把它当已定位，用户必须缩小去找。现在右栏画布把视口中心写进共享状态，建卡时换算出卡片左上角坐标随 `create_card` 一次写库；未拿到视口时回落 0,0，由下次刷新按中心补位。

- 0.23.0 修复**缩小后拖拽卡片像卡死**：React Flow 在节点拖拽时逐帧重建视口内所有节点，338 个节点同屏就是每次拖拽近 8,000 次重渲染。现在 <45% 缩放时节点降级为标题条、边全部收起、尺寸不回写，拖拽改为平移画布；45% 以上照常拖卡片。同时修掉 KaTeX 缓存满 400 条整体清空导致的反复重排、拖拽时占用忙碌锁引发的两轮全画布重渲染。

- 0.22.0 解决**导入 1483 张 Anki 卡片后画布加载极慢**：根因不是数据量，而是把 1483 个节点全挂到 DOM（3.3 万元素），外加每个节点用 store selector 扫全表算子节点（O(n²)）。现在按视口裁剪只挂载屏幕内节点、子节点数改成工作区预算表、只在缺坐标时才重排、大图不做全量 fitView、大纲按 200 行追加、>400 节点关掉 MiniMap。详见 [大画布性能](docs/mindmap-performance.md)。

- 0.21.0 把复习卡正面「请在心里组织答案」这句静态提示换成**答案输入框**：揭示背面后按本地加权 F1 给出匹配度、评价与已写到 / 待补上的要点词，输入可继续修改并实时重算。揭示前不渲染任何答案要点，输入不落库、不参与 FSRS 评分；`scripts/review-answer-smoke.mjs` 覆盖完整链路与降级分支。

- 0.20.0 新增**多画布与 AnkiDroid txt 导入**：schema 升到 v9（`mindmap_canvases`），归属复用 `mindmap_layout` 复合主键，`surface_mindmap` 变成派生开关；建卡、整理、清空、拆书、导入全部按 `canvasId` 作用域。备份 overwrite / merge 纳入画布表，旧备份自动补回 `main`。`STEP=canvas` / `STEP=anki` 回归覆盖画布隔离、切换不卸载 React Flow、画布 CRUD、牌组勾选与导入不串画布。

- 0.19.0 修复**AI 解析后笔记看不全**：卡片正文原先被 `-webkit-line-clamp: 3` 写死截断且无滚动条。现在长文本可点击展开、展开区限高滚动，AI 解析写回后自动展开；大纲行补上笔记并支持同样的展开交互。`STEP=note-expand` 回归覆盖自动展开、滚动条、滚轮不平移画布、收起 / 再次展开与大纲笔记。

- 0.18.0 新增**可设 AI 拆分层级**（默认 2 层，1–5 层，偏好持久化）：解决厚书「一章多小节、小节多名词、名词还有解释」只能拆出两层的问题。阶段一/阶段二提示词、节点预算、解析截断与父子卡片布局都随层数联动。

- 0.17.0 修复**自动整理后卡片散落且缩放过小**（森林网格打包 + 整理后 fitView）；新增**批量清空脑图卡片**（仅移出脑图 / 彻底删除，单事务、带确认框）。

- 0.16.0 修复**大纲切回画布后卡片空白**（画布改为常驻，大纲只是覆盖层，不再卸载重建 React Flow）；新增**拆书卡片页码标签 + 点击跳回原文**、**卡片 AI 解析问题**（结果写入笔记）。

- 0.15.0 新增 **AI 拆书**：分块抽取（结构 / 智能词典 / 英文生词 / 题目四种模式）→ 汇总成层级骨架 → 批量写入卡片与脑图；节点保留原文摘录与页码，可回跳来源。两阶段都落库，超过 100 页可中断续跑。

- 0.14.0 新增**留白（页边草稿）**：右键页面空白添加，贴在页面右边缘，失焦保存、可折叠/删除；数据存 `page_notes`（schema v7），随备份往返并参与合并导入。

- 0.13.2 修复**卡片里的公式被裁掉**：卡片正文原本按 3 行截断（`-webkit-line-clamp`），块级公式高度远超 3 行，右侧和下半部分会被切掉。现在含公式的段落自动取消截断，公式按卡片宽度等比缩放（基准 11px，下限 70%），过长时才横向滚动。

- 0.13.1 修正**公式卡片重复显示**：摘录已经能排版成公式时，不再显示选区截图，避免图片挤占空间把公式遮住；纯图片卡片（OCR 没取到文字）仍保留截图。

- 0.13.0 新增**公式渲染**：KaTeX 本地渲染卡片里的 LaTeX（脑图节点、大纲、复习卡背面），裸 LaTeX 与 `$...$` 混排都能识别，原始源码保留可编辑。同时修正脑图画布导航：**左键拖空白即可平移**、触控板双指滑动平移、`⌘`+滚轮或捏合缩放，框选改为按住 `Shift`。

- 0.12.7 修好**任务结果取不回来**：本机网关把识别结果放在 `result_text`，此前解析器只认 `latex`/`content`/`result`，于是明明 `SUCCEEDED` 却轮询到超时。现在 `result_text` 优先解析，并加了“最长非元数据字符串”兜底，网关改字段名也能取到。识别失败的状态栏改为**一句摘要 + 重试按钮 + 默认折叠的「查看详情」**，详情里可复制完整错误与任务号。

- 0.12.6 让公式识别真正对齐 Mathpix：提示词先判断图片中是否存在科学公式，有公式则输出 Mathpix 兼容 LaTeX（保留 `\frac`、`\sum_{i=1}^{n}`、`\log_2`、上下标结构），无公式则输出文字。网关 504 后的任务结果解析更宽容（`data.latex`、嵌套 `content` 数组、`result.output` 等），首次立即查询；设置面板新增「按任务号取回结果」，可对已完成任务直接取回 LaTeX 并复制。

- 0.12.5 处理**网关 504 超时**：当服务端在自己的 90 秒上限先返回 504 并给出异步任务号时，应用会自动轮询 `/tasks/{task_no}` 取回识别结果，而不是直接失败；设置面板新增可调超时（30–300 秒），提示文案也改用实际配置值。

- 0.12.4 修复**脑图删卡后 PDF 标注不联动**：卡片删除后 PDF 工作区的标注缓存仍是旧值，页面上留下点不掉的“幽灵标注”，点击删除报 `annotation not found`。现在卡片删除会广播事件，PDF 立即清理对应标注并让相关页重新对齐；后端已无此标注时也不再报错，而是自愈移除并说明。

- 0.12.3 修复**安装后 Launchpad 找不到图标**：此前 Tauri 产物只有链接器自动签名（`Identifier` 与 bundle id 不一致、`Info.plist` 未绑定、资源未封印），LaunchServices 无法正确注册。现在 `bundle.macOS.signingIdentity` 固定为 `-`，每次构建都对整个 bundle 做 ad-hoc 签名并封印资源（`codesign --verify --strict` 通过）。

- 0.12.2 修复**画布右键折叠节点不生效**：可见性算法的兜底循环把被折叠的子节点又加了回来。同时：设置面板新增「测试连接」（验证地址、鉴权与模型名）；公式识别不再只覆盖 OCR 来源，文字层公式也会走视觉模型，并带秒级进度与 120 秒超时提示。

- 0.12.1 修复**切「大纲」必崩的 React #185**：受控 nodes 下选择回调在 React Flow 更新阶段同步 setState，形成更新回路。选择改由 `select` change 驱动并合并到下一帧；拖拽中不回写位置；测量回写加容差与熔断；React Flow 的对象/数组 prop 全部常量化。新增 `scripts/mindmap-regression.mjs` 作为回归红线。详见 [React #185 复盘](docs/react-185-regression.md)。

- 0.12.0 新增**可选 AI 识别**：公式选区可交给配置好的视觉模型转 LaTeX，默认不配置即完全离线；设置文件独立于数据库与备份包。详见 [可选 AI 识别](docs/ai-recognition.md)。

- 0.11.0 新增**标题链接**：卡片标题与别名成为本地关键词字典，阅读任意文档时命中词自动高亮，点击回看原卡片并跳回来源页。schema 升至 v6（`cards.link_aliases`），旧备份导入时自动补空别名。详见 [标题链接](docs/title-link.md)。

- 0.10.1 修复**文字选区重影**：选区高亮此前会把文字层里被拉伸的 DOM 字形一并画出来，与 PDF 真实字形错位形成“双层文字”。现在选区只绘制半透明底色，字形始终保持透明。
- 0.10.0 用**应用内右键菜单**替代 WKWebView 只有 Reload 的原生菜单：按选中的文字、标注、墨迹、脑图节点等元素提供就地操作；输入框仍保留系统复制/粘贴菜单。详见 [应用内右键菜单](docs/context-menu.md)。

- 0.9.0 加入**可选文字层**：Apple Vision 返回的每行坐标不再丢弃，整页识别一次后铺成透明 DOM 文字层并缓存到 SQLite（`page_ocr`，schema v5）。「文字」工具下可像 Word 一样拖选、复制、建卡；框选建卡也优先读缓存文字，不再每次等待 OCR。有 PDF 文字层的页面直接用精确字形坐标，完全不走 OCR。
- 0.8.0 把 OCR 切换为 **Apple Vision 单引擎**：移除 Tesseract.js、WASM core 与约 63MB 离线语言模型，安装包大幅缩小；原生引擎失败时明确报错并保留选区图像，不再静默降级。详见 [Apple Vision OCR](docs/ocr.md)。

- 0.7.0 处理公式选区：纯文字 OCR 无法识别公式结构，检测到公式特征时保留选区原图（`cards.excerpt_image`），不写入乱码文本；扫描页图像摘录同样随卡片存档，脑图节点、复习闪卡与编辑器均可查看。schema 升至 v4。崩溃时错误与 React 组件栈写入 app 数据目录 `logs/crash-*.log`。

- 0.6.0 补齐标签、链接、墨迹、合并四项能力，schema 升至 v3，详见 [卡片能力](docs/card-features.md)。

- 0.5.0 新增脑图大纲模式与 Markdown 导出，详见 [大纲与导出](docs/outline-export.md)。

- 0.4.0 重构界面为“左文右图 + 悬浮工具栏”的工作台布局，详见 [工作台布局](docs/workspace-layout.md)。

- 新增“继续阅读”：每份 PDF 记录上次停留页，重新打开自动定位；旧版备份仍可导入。

- 修复进入脑图视图后 React #185（Maximum update depth）导致界面中断：选择回调改为内容比较，节点补齐 measured 尺寸。详见 [脑图崩溃复盘](docs/react-185-regression.md)。
