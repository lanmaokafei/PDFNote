# AI 拆书：把厚书变成可学的结构（0.15.0，0.18.0 起可设层级）

目标：一键把论文 / 教材拆成「问题驱动」的脑图骨架，每个节点带原文摘录与页码，可回跳来源。
超过 100 页也能跑：**先笔记、后整理**，分块处理且可中断续跑。
0.18.0 起读者可指定**拆分层级**（默认 2 层，最深 5 层），把「章 → 小节 → 名词 → 解释」这类四层结构一次拆出来。

## 两种阶段

| 阶段 | 做什么 | 存在哪里 |
| --- | --- | --- |
| ① 先笔记 | 每 8 页（可调 2–30）一块，抽取摘要 + 条目（标题 / 摘录 / 页码 / 别名）；深层拆解时多抽名词与定义 | `book_analysis`，按 (文档, 模式, 块号) 唯一，重跑只补未完成的块 |
| ② 后整理 | 把所有块的笔记汇总成层级骨架，层数与节点预算由读者设置决定 | `book_outline`（`outline_json` 里带 `depth`） |
| ③ 写入 | 骨架落成卡片 + 脑图坐标，父子关系按层级写入，节点通过 `page + bbox` 链回原文 | `cards` / `mindmap_layout` |

写入时**不创建 annotation**：节点在 PDF 上不会画整页高亮，但卡片保留来源页与位置，可从卡片回跳。
重复点「写入脑图」按「同文档 + 同标题」去重，不会翻倍。

## 四种姿态

| 模式 | 抽什么 | 适合 |
| --- | --- | --- |
| 结构 | 背景 / 方法 / 结果 / 讨论，或章节要点 | 论文、教材通读 |
| 智能词典 | 术语 + 定义 + 别名（`aliases` 写进 `cards.link_aliases`） | 与标题链接联动，术语自动成为关键词 |
| 英文生词 | 单词 / 短语，按 CEFR（A2–C2）分级，附原句与释义 | 英文教材、paper 精读 |
| 题目 | 把内容转成可自测的问题，答案取原文 | 应试、复习前自检 |

## 拆分层级（0.18.0）

向导里新增「拆分层级」下拉，**默认 2 层**，可选 1–5 层；选择写入 `localStorage` 的
`pdfnote.digest.depth`，下次打开向导（甚至重启应用）仍保持。设置是「按读者」保存的本地偏好，
不随文档或模式切换而重置。

| 层数 | 结构 | 适合 |
| --- | --- | --- |
| 1 | 只列主题 | 快速鸟瞰 |
| 2（默认） | 主题 → 要点 | 快速通读，节点最少 |
| 3 | 主题 → 要点 → 名词 | 概念密集的章节 |
| 4 | 章 → 小节 → 名词 → 解释 | 教材 / 论文精读，解决「一章分很多小点、小点里还有名词和解释」 |
| 5 | 四层 + 参数 / 边界 / 反例 | 备考、易错点整理 |

层数不是摆设，会同时改变三段行为：

1. **阶段一**：`analyze_book_chunk` 收到 `depth`，条目上限从 10/12/15 条放宽到最多 24 条；
   深度 ≥3 时提示词额外要求「抽取要点下的具体名词、术语、参数及其定义」，否则第 3/4 层没有素材。
2. **阶段二**：`synthesize_book` 收到 `depth`，提示词按模式生成逐层语义（例如结构模式第 3 层是
   「核心名词 / 概念 / 方法名」、第 4 层是「定义、成立条件、公式含义或举例」），并给出**恰好 N 层**
   的嵌套 JSON 示例；笔记摘要会带上摘录原文，节点预算按 `80 + (depth-2)×30` 放大（2 层 80、5 层 170），
   输出 token 上限同步提高到 8000。
3. **解析与写入**：`parse_outline_nodes` 按所选层数截断（另有 6 层硬安全网），`apply_book_outline`
   递归建卡，`parent_id` 层级与 `mindmap_layout.x = depth × 320` 一一对应，深层节点也能回跳原文。

骨架预览会显示「节点数 · 实际层数 / 目标层数」，并在每行前标 `L1`…`L5`。若模型偷懒只给了两层，
提示会直接说明并可再汇总一次；切换层数会**清掉旧骨架**（避免把旧深度的结构写进脑图），但保留
已完成的块笔记，可以直接重新汇总。想让阶段一也按新深度重抽素材，点「清空重来」再分析即可。

## 入口

- 文档工作台顶部「AI 拆书」（非嵌入布局）；
- 底部工具坞 →「更多」→ 菜单顶部「AI 拆书」（嵌入布局也能用）；
- 向导内可切模式、选页码范围（全书 / 当前页附近 / 手动），随时「清空重来」。

## 文本从哪来

- **有文字层的 PDF**：pdf.js `getTextContent()`，顺带算出每页文字区域的归一化包围盒；
- **扫描页**：回退到 Apple Vision 的行级 OCR 缓存（`page_ocr`），没有缓存就跳过该页并计入进度。

所以「Vision 负责看扫描页、LLM 负责结构化」，与既有 OCR 管线一致；未引入 Core ML 本地模型，
文本模型仍走「设置」里配置的 OpenAI 兼容通道（本机 Ollama / LM Studio 或云端）。

## 数据模型（schema v8）

```sql
book_analysis(document_id, mode, chunk_index, page_start, page_end,
              summary, items_json, pages_json, created_at, updated_at)
book_outline(document_id, mode, outline_json, updated_at)
```

两表都以 `document_id` 外键级联删除；整库备份/恢复与合并导入都会带上（合并时按内容哈希重指向本地文档）。

## 稳健性

- 模型输出容忍代码围栏与前后解释：从第一个 `{` 到最后一个 `}` 兜底解析。
- 页码会校验在分块范围内，越界引用降级为 `null`；标题截断 80 字、摘录 600 字。
- 单块上限 24 000 字；汇总提示词默认截断 20 000 字，深层时按 `20 000 + (depth-2)×4 000` 放宽，避免上下文爆掉。
- 汇总结果按所选层数截断，节点预算 80（2 层）到 170（5 层），并有 6 层硬安全网，防止模型输出失控。
- `depth` 取值收敛到 1–5；非法值直接报错。旧备份里的 `outline_json` 没有 `depth` 字段时按 2 层反序列化，不影响读取。
- 某一块失败不会丢掉已完成块：重新点「继续分析」只会补未完成的块。

## 写入脑图之后（0.16.0）

- 卡片头部会显示 `P3` 这样的来源页码标签（数据来自 `cards.document_id + page`，即 `source_ref`）。
  点击标签会派发 `pdfnote:open-source`，App 切到对应文档并让左侧 PDF 滚到该页；
  若文档还没打开，会先按 id 找到并打开。跳页带 60 / 400 / 1200ms 重试，等页面占位元素注册完成。
- 按 CEFR 等级或主题分组的一级节点常常没有 `page`，写入卡片时会**继承子树第一个页码**，
  保证每张拆书卡片都带来源、都能回跳。不建 `annotations`，PDF 页面不会被整页高亮盖住。
- 带 Q（问题）的卡片底部有「AI 解析」按钮，右键菜单里也有同名入口。模型按
  「是什么 / 为什么 / 怎么用 / 易错点」四段解释，结果以 `【AI 解析】` 追加到卡片笔记。
  复用拆书的纯文本模型通道，未配置模型时会提示先去「设置」填写 Base URL 与模型名。

## 限制

- 拆书质量取决于模型与文字层质量；扫描页依赖 OCR 缓存，倾斜 / 竖排页可能抽错。
- 节点原句可能被模型轻微改写（提示词要求照抄），重要结论需回原文核对。
- 层数由提示词约束，模型仍可能给不足层数（预览会提示实际层数），特别是在分块页数过多、
  笔记条目太少时；此时缩小每块页数或清空重来再分析更可靠。
- 深层骨架写进脑图后是一棵较深的树，可用工具栏「自动整理」重新排布；单棵树叶子很多时仍会偏长。
- 不做「AI 浮球」常驻面板；入口在文档内，模式与层数切换都在向导里。
- 生成的是独立卡片（`surface_pdf = 0`），不会自动进入 PDF 侧栏标注列表。

## 验证

```bash
npm run dev -- --host 127.0.0.1
STEP=digest CARD_COUNT=12 node scripts/mindmap-regression.mjs
STEP=depth CARD_COUNT=12 node scripts/mindmap-regression.mjs
STEP=card-actions CARD_COUNT=12 node scripts/mindmap-regression.mjs
STANDALONE=0 STEP=outline-back CARD_COUNT=12 node scripts/mindmap-regression.mjs
STEP=outline-back CARD_COUNT=12 node scripts/mindmap-regression.mjs
```

冒烟覆盖：打开向导 → 分块分析（调用 `analyze_book_chunk`）→ 汇总（`synthesize_book`）→
写入（`apply_book_outline`），并断言分块笔记确实落库。

`depth` 覆盖：默认 2 层 → 选 4 层 → 写入 `localStorage` → 刷新页面后设置仍生效 → 阶段一与阶段二
命令都收到 `depth=4` → 预览渲染到 `L4` 且统计为 4 节点 / 4 层 → 写入 4 张卡片 → 改回 2 层后
旧骨架失效、命令参数同步变成 2、预览不再出现第 3 层。

`card-actions` 覆盖页码标签渲染 → 点击派发跳页事件 → AI 解析调用模型并写回笔记；
`outline-back` 覆盖大纲切回画布后画布实例不被卸载、节点仍在可视区域（独立与嵌入两种模式）。

Rust 侧另有 10 项测试：JSON 容错解析、页码越界丢弃、骨架写入卡片与布局（含重复应用去重、
不生成 annotation）、分组节点继承子节点页码、按读者层数截断、depth 合法性与节点预算、
4 层提示词与嵌套示例、阶段一深层提示词、旧 `outline_json` 兼容、4 层父子链与布局落库。
前端 `depth.test.ts` 另覆盖取值收敛、持久化与层数/节点数统计。
