# 脑图自动整理与清空卡片（0.17.0）

## 自动整理为什么会「散」

旧版 `buildTreeLayout` 把所有根节点依次向下堆：每棵独立树占一行，行距 250px + 树间距 60px。
26 张互不相连的卡片会变成一条约 8000px 高的竖条，`fitView` 只能把缩放压到 0.09 左右，
卡片小到看不清，看起来就像散落在画布各处。

另外，整理按钮只写库与更新坐标，**没有重新对齐视口**；用户仍停在整理前的平移/缩放位置，
即使坐标已经聚拢也看不到。

## 现在的做法

1. **森林网格打包**（`src/features/mindmap/layout.ts`）：
   - 每棵树先单独算相对坐标与包围盒（宽 = 最大深度 × 360 + 254，高按叶子数 × 250 + 卡片高度）。
   - 再按「目标长宽比 1.6」估算行宽，贪心按行摆放；行间 120px、树间 90px。
   - 26 张独立卡片约排成 6 列 × 5 行的紧凑网格，整体约 2000 × 1400，缩放约 0.5，卡片可读。
   - 单棵树仍保持左父右子、父节点纵向居中；环状父子关系与孤儿卡片仍有兜底坐标。
   - 已有布局坐标会被忽略并整体覆盖，所以「自动整理」是确定性的，可重复点。
2. **整理后对齐视口**：`autoArrange` 保存坐标 120ms 后调用 `fitView`（320ms 动画），
   嵌入分栏视图也会执行；定时器在组件卸载时清理。
3. **入口**：独立脑图工具栏「自动整理」、画布右键「自动整理节点」、分栏脑图悬浮坞「整理」。

布局函数不改数据库结构；坐标写入 `mindmap_layout(canvas_id, card_id)`。0.20.0 起 `canvas_id` 是当前选中的画布，不再是写死的 `main`，因此整理只影响当前画布，其它画布坐标保持不变；详见 [多画布脑图](mindmap-canvases.md)。

## 清空卡片

工具栏「清空卡片」、分栏悬浮坞「清空」、画布右键「清空脑图卡片…」打开同一个确认框，
显示当前脑图卡片数量，提供两种不可逆程度不同的操作：

| 模式 | 后端命令 | 语义 |
|---|---|---|
| 仅清空脑图 | `clear_mindmap_cards({ mode: 'remove', canvasId })` | 只删**当前画布**的 `mindmap_layout`；卡片若仍在其他画布则不动父子结构与 `surface_mindmap`，完全离开脑图才关投影；卡片、PDF 标注、复习记录仍在 |
| 彻底删除 | `clear_mindmap_cards({ mode: 'delete', canvasId })` | 删除当前画布上的卡片本体；annotations / review_logs / card_tags / card_links / **所有画布的** mindmap_layout 靠外键级联清除 |

两种模式都在 Rust 单事务里完成，返回受影响数量；前端随后清空当前画布的坐标、测量缓存、选中、链接与弹窗，
再刷新卡片状态。`clear` 的作用域是**当前画布的成员**（`mindmap_layout.canvas_id = 当前画布`），
其它画布不受影响（「彻底删除」因删除的是卡片本体，会连带清掉它在其它画布的布局）。
删除前请先在设置里做一次备份。

实现细节：`cards.parent_id` 是自引用外键（`ON DELETE SET NULL`），批量删除前会先把所有
父子引用置空，避免逐行级联触发隐式 FK 更新。

## 验证

```bash
# 26 张互不相连的卡片：断言网格长宽比、全部坐标落库、整理后缩放不低于 0.2
ARRANGE_FOREST=1 STEP=arrange CARD_COUNT=26 node scripts/mindmap-regression.mjs
# 两种清空模式往返（remove 保留卡片 / delete 清空卡片与节点）
STEP=clear CARD_COUNT=12 node scripts/mindmap-regression.mjs
```

Vitest 另有 4 项布局单测（紧凑网格、网格不重叠、单树父子关系、环状兜底）；
Rust 另有 2 项测试（remove 保留卡片但清投影与坐标、delete 级联清理并拒绝非法模式）。

## 限制

- 只有多棵独立树会网格化；**一棵叶子极多的深树**仍会纵向很长，这是层级布局的固有代价。
- 「彻底删除」不可撤销，也没有回收站；应用内没有二次输入确认（只有确认框与模式选择）。
- 清空后不会自动重建布局；新建卡片会从 `buildTreeLayout` 的新森林重新开始。

## 新卡落点：跟随视口中心（0.24.0）

在 PDF 上划重点建卡时，读者眼睛在左栏、卡片却生成在脑图原点 `(0,0)`，必须缩小再去找——这是 0.24.0 之前的行为。现在新卡落在**右栏画布当前的视口中心**。

### 怎么算的

- 脑图在 `onMoveEnd`、首次加载与刷新后，把「视口中心 → 世界坐标」写入 `src/features/mindmap/viewport.ts` 的模块级共享状态。
- 建卡方（PDF 划重点、脑图「新建」）调用 `nextMindmapInsertPoint()`：以中心点减去卡片估算尺寸（254×190）得到左上角坐标，并按 3×3 环每次错开 36px，连续建卡不会叠成一摞。
- 坐标随 `create_card` 的 `x` / `y` 一起写入 `mindmap_layout`，不再先写 0,0 再补一次。
- 切换画布时重置错开序号，新卡重新从正中心开始。

### 兜底

- 右栏脑图被收起或尚未挂载时读不到视口中心，`nextMindmapInsertPoint()` 返回 `undefined`，后端写 0,(0)。脑图下次刷新会把 `(0,0)` 视为「未定位」（这是 layout 列的默认占位值），按当前视口中心补位。
- 一次刷新里有多张未定位卡片时，第一张用视口中心，其余依次向下排 210px。
- 旧版本留下的 `(0,0)` 卡片也会在升级后的第一次刷新被带到视口中心，不需要手动整理。

### 回归

```bash
STEP=insert-center CARD_COUNT=3 node scripts/mindmap-regression.mjs
```

场景会先把画布平移到别处，再连续新建两张卡，断言第一张的坐标等于「视口中心 − 卡片尺寸/2」（±3px）、第二张比第一张右移 36px，并确认不再使用旧的固定坐标。
