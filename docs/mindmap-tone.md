# 脑图卡片配色：二十四节气色

版本：0.27.0

## 为什么换

0.26.0 之前，整张脑图所有卡片都是同一套色：白底、灰绿描边、深绿 Q 徽标。单看一张卡片很干净，但一千多张卡铺开之后，读者完全看不出「哪几页属于同一个知识点」，只能靠位置和连线去猜。

MarginNote 的做法值得借鉴：卡片本身保持白底（长文必须可读），**颜色只用在标记位**——色条、徽标、标签——并且颜色是「分类信息」而不是装饰。它的社区还按学科场景发布了整套色卡（彩虹、糖果、人民币、莫兰迪、淡彩），说明用户确实会把颜色当检索维度。

PDFNote 需要一个同样有语义、又不吵闹的色板。选了《中国传统色》的二十四节气体系：每个节气有四个传统色（起承转合），96 个色足够挑，而且它天然带一条「春黄 → 夏红 → 秋赭 → 冬紫」的色相推进，比随机生成的调色板更耐看。

## 三档派生

每个主色在 `src/features/mindmap/tone.ts` 里派生三个值，**不手写**（避免 72 个色值出现人为偏差）：

- `bar`：主色本身。用于左侧色条、徽标描边、选中光晕、页码 chip 边框。
- `wash`：主色与白色按 8% 混合。用于卡片标题栏底色、低缩放标题条底色、hover。
- `ink`：主色压到约 30% 亮度、保持原饱和度。用于淡底上的徽标字与页码字。

`ink` 的亮度取 `min(0.30, 主色亮度 − 0.18)`：深色主色（石绿、柔蓝）如果按固定亮度压，压出来的「深字」反而比主色更亮。饱和度不抬下限——灰调色（白露·千山翠）压深后仍应是灰调，不能变成鲜绿。

单测里有一条硬约束：**每个 `ink` 在对应 `wash` 上的 WCAG 对比度必须 ≥ 4.5:1**。加一个新色如果读不清，测试直接失败。

## 分配规则

卡片不存颜色。颜色由「所属子树的根节点 id」稳定哈希到 24 个色相之一：

```
卡片 → 沿 parent_id 找到子树根 → FNV-1a 哈希 → % 24 → 节气色
```

这样处理的原因：

- **一簇一色**。同一棵子树的所有卡片同色，脑图铺开时自然形成彩色簇群，比每张卡随机一色更有信息量。
- **稳定**。哈希只依赖 id，与加载顺序、卡片增删、画布切换都无关；拖动、整理、折叠不会让颜色跳来跳去。
- **O(n)**。`toneIndexMap()` 带路径压缩，1483 张卡只遍历一遍；节点内不做任何父链查找（那是 O(n²) 的老坑）。

父卡不在当前画布时（跨画布父子、卡片被删），当前可见链的顶端就是这棵树的根；父子链成环（历史脏数据）时退回起点，不会死循环。

## 手动换色

两条路：

1. **卡片右键 → 外观 → 卡片样式…**：面板顶部是完整的二十四节气色板，点色块直接指定颜色；「跟随子树」清掉指定，回到按子树自动分配。
2. **点卡片左上角的 Q 徽标**：换下一个节气色（24 次一轮），适合快速试几下。

两条路写的是同一份数据（`localStorage` 的 `pdfnote.mindmap.tone`）：

```json
{ "card-uuid": 13 }
```

只存被手动改过的卡片，默认配色的卡片不落任何数据。读的时候一次性读进内存，之后查表——不会出现「1483 张卡各读一次 localStorage」。

手动色作用于**单张卡**，不会带动子树。想让整簇换色，目前需要逐张点（批量换色留到后续）。

## 视觉规格

| 部件 | 处理 |
| --- | --- |
| 卡身 | 纯白 `#ffffff`，1px 中性边框 |
| 左色条 | 3px 主色，是这张卡最主要的身份标识 |
| 标题栏 | `wash` 淡底（8% 主色） |
| Q 徽标 | 白底 + 主色描边 + `ink` 字 |
| 页码 chip | 白底 + 主色描边 + `ink` 字 |
| 选中 | 3px 主色光晕（主色 22% 透明）+ 加深阴影 |
| 低缩放（lite） | 整块 `wash` 底 + 3px 色条 + `ink` 字；不画边框细节 |
| 大纲行 | 左侧 3px 色带（`inset box-shadow`，不占缩进），hover 用 `wash` |

低缩放那一条尤其重要：缩到 15% 时文字已经不可读，**颜色是唯一的辨认依据**。所以 lite 模式虽然砍掉了 KaTeX、图片、按钮、连线，却保留了色调类与淡底。

## 验证

```bash
STEP=tone ARRANGE_FOREST=1 CARD_COUNT=26 node scripts/mindmap-regression.mjs
```

断言：

- 26 张互不相连的卡片出现 ≥ 10 种色调（实测 17 种），没有节点丢色调类；
- 色调类数量与 CSS 变量数量一致（防止类名漏进 CSS）；
- 卡身是纯白（颜色只在标记位，不污染正文底）；
- 点徽标后色调变化，且 `localStorage` 里的序号与画布一致；
- 缩到低倍后 lite 节点仍带色调与淡底。

单测（`src/features/mindmap/tone.test.ts`，15 项）覆盖色板完整性、三档明暗关系、对比度下限、色相季节分布、越界回绕、路径与防环、覆盖读写。

## 性能

- 色调计算是纯前端 O(n)，1483 张卡实测增加 < 2ms（`STEP=perf` 首节点仍 ~0.9s）。
- 节点只多一个 `--tone-*` 类名，样式全部走 CSS 变量，不写 inline style——节点 memo 的比较字段没变，低缩放拖拽的重渲染仍是 0。
- `localStorage` 只在初始化与换色时读写，不在渲染路径上。
