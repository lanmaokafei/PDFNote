# PDF 全书搜索（0.57.0）

工具栏/工具坞的 **搜索** 按钮或 `⇧⌘F` 打开；`⌘F` 保留给系统查找，不抢键。

## 怎么工作

1. 打开面板时**懒建一次索引**：按页从 PDF 文字层取文本（`getTextContent`），
   每页记录行文本与归一化矩形；空页（扫描件）再退回 `page_ocr` 的 Vision 缓存。
2. 索引顺序执行（不并发）：pdf.js 的 worker 与页面渲染共用通道，并发抽取会让滚动卡顿。
   每 4 页让出一帧，输入事件不被堵住。
3. 查询直接跑内存索引：大小写不敏感的子串匹配，中文按字、英文按字母，单次最多 500 处；
   面板先显示前 80 条，继续输入缩小范围。
4. 点结果或按 `Enter / Shift+Enter` 跳页；命中的行会以黄色矩形标在当前页上（只画当前命中）。
5. 索引期间计数显示「已索引 / 总页」，建完变成「N 处」；结果随索引增长。

## 边界

- 索引只在内存里：切换文档或重启应用会重建；上限 1200 页（超出部分不索引）。
- 只有 **PDF 文字层** 与 **已缓存的 OCR 页** 可搜：没打开过的扫描页没有 OCR 缓存，搜不到；
  想搜到就先翻一遍让它生成文字层，或直接用目录骨架。
- 子串匹配，不支持正则、词干、模糊/近似匹配；英文不做词边界判断（`line` 会命中 `linear`）。
- 高亮按文本项矩形画，一个 item 内有多处命中时整行都会标；跨行的短语可能只标到第一行。
- 页码来自 PDF 内部页序，与书上手写页码可能不一致。

## 验证

```bash
STEP=pdf-search CARD_COUNT=3 node scripts/mindmap-regression.mjs
```

断言：索引完成后计数为「1 处」、结果行含 `line`、点击后高亮层有矩形且结果项为选中态、
`Enter` 切到下一处仍只有一个高亮、`Esc` 关闭后高亮清空。纯函数单测覆盖：
大小写不敏感、一行多处命中、500 条上限、摘要省略号、OCR 行转换、文字层 transform 换算、
非法变换跳过。
