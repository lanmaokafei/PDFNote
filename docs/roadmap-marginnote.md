# 对照 MarginNote 的优化方案

> 来源：`marginnote.com.cn/features/{card-axis,title-link,extended-note,ai}` 四个功能页
> 日期：2026-11-03 · 基于 PDFNote 0.10.1 现状

## 一、总体结论

卡片轴心架构我们已经对齐（Card 单一对象三视图渲染），真正的差距集中在三块：**标题链接（完全缺失，但我们的地基比想象的好）、留白（完全缺失）、AI 能力（完全缺失，且与离线定位需要谨慎调和）**。

按「价值 ÷ 成本」排序的实施优先级：

| 优先级 | 功能 | 现状差距 | 成本 | 关键依据 |
|---|---|---|---|---|
| **P0 · 已完成 0.11.0** | 标题链接（自动反向链接） | 已实现 | 小 | 页面文本已缓存（schema v5），纯本地匹配，MN 自己也不用 AI |
| **P1 · 已完成 0.12.0（公式）** | 公式/表格 OCR | 公式已可转 LaTeX；表格仅后端接口 | 中 | 本机 VLM 或可选云端，直接消灭 known-limits 里的一条 |
| **P2 · 已完成 0.14.0（页边模式）** | 留白（页边草稿） | 页边便签已实现；嵌入模式未做 | 中 | 先做页边模式，嵌入模式工程量大后置 |
| **P3** | AI 出题（挖空）+ AI Hint | 复习只有问答卡 | 中 | 复用 P1 的模型通道 |
| **P4** | 智能 TOC / AI 拆书 / 框架重组 | 扫描书无目录 | 大 | 重型功能，等模型通道稳定后再议 |

## 二、逐项对照

### 1. 卡片轴心（card-axis）—— 已对齐，无需返工

| MN 能力 | PDFNote 现状 |
|---|---|
| 摘录即建卡 | ✅ 高亮/框选/文字选区/图像摘录均直接建卡 |
| 卡片即节点（同一对象） | ✅ 同一 Card 渲染为 PDF 高亮、ReactFlow 节点、复习闪卡 |
| 复习是 surface（FSRS） | ✅ ts-fsrs 队列，状态写回同一卡片 |
| 来源回跳（页码+位置） | ✅ annotation bbox + `last_page` 恢复 |
| 标题链接/留白/回忆模态建立在卡片原子上 | ⚠️ 回忆模态已有（遮挡块），另两项缺失 |

**可借鉴的细节**：MN 强调「卡片标题 = 字典条目」——我们的卡片目前标题（question）只是展示字段，没有发挥其「可被检索/被匹配」的第二价值。这正是 P0 的切入点。

### 2. 标题链接（title-link）—— 最大性价比缺口

**MN 机制**：卡片标题自动注册为关键词（一卡多词，分号分隔别名）→ 打开任意文档时扫描页面文本 → 命中词自动高亮 → 点击弹出原卡片（注释+来源）。跨文档统一字典，纯本地即时匹配。

**我们已有的地基**：
- `page_ocr` 缓存了每页文本（Vision 行级 + PDF 文字层），匹配输入现成；
- `cards` 有标题字段，`card_links` 表结构可复用或旁路；
- 文字层 DOM 已支持按行 bbox 定位，命中词高亮可以复用同一套定位。

**实现方案（schema v6）**：
1. `cards` 增加 `link_aliases TEXT`（分号分隔别名，空则用 question 作为主关键词）；可选独立 `title_keywords` 表做倒排，卡片数 <1 万时直接内存字典即可。
2. Rust 或前端 Worker 构建关键词字典（Aho-Corasick 多模式匹配，中文按字匹配、英文按词边界）。
3. 打开页面 → 取 `page_ocr.lines_json` 文本 → 匹配命中 → 在文字层下方渲染半透明下划线/底色高亮（新增独立 `pdf-titlelink-layer`，z-index 低于选区）。
4. 点击命中词 → 弹出卡片预览（复用 CardEditor 只读态），带「跳转到来源」按钮。
5. 开关：设置项 + 工具栏切换，默认关（避免新用户无卡库时无意义开销）；短词（<2 字）不入字典，控制误报。

**明确不做**：不链卡片正文（MN 也只链标题，避免视觉污染）。

### 3. 留白（extended-note）—— 先做页边模式

**MN 机制**：长按 PDF 任意位置开独立草稿，不绑定文本；普通（嵌入页面，纸面长大）/ 页边 / 折叠三模式；支持手写文本图片，可选卡片化。

**我们现状**：`page_inks` 是手写笔画（有），卡片注释绑定文本（有），缺的是「页面级独立文本草稿」。

**实现方案（分两期）**：
- **一期（页边+折叠，schema v6）**：`page_notes` 表（document_id, page, anchor_y, content, mode, created_at/updated_at）。在 PDF 页右侧页边渲染便签卡片，可编辑纯文本/Markdown 轻量子集；折叠成小圆点。入口复用 0.10.0 右键菜单「页面空白 → 添加留白」+ 长按（触屏）。
- **二期（嵌入模式）**：纸面长大需要改页面渲染管线（在 canvas 下方插入动态高度区块并推挤后续内容），与现有虚拟化滚动有冲突，单独评估后再做。
- 手写复用 `page_inks`；「标记为卡片」= 建一张无摘录仅 note 的卡（现有 schema 已支持）。

### 4. AI —— 与离线定位的调和

**原则**：默认离线、模型可选、AI 输出一律视为草稿（MN 自己也强调 Accept/Reject）。模型通道二选一或并存：
- **本机**：M4 24GB 可跑 7-14B Q4（llama.cpp / MLX）。公式/表格识别用 VLM（如 Qwen2.5-VL 7B 级别）；文本任务用 Qwen 系。
- **云端**：用户自填 API Key（OpenAI 兼容协议），默认关闭，UI 明示「此功能联网」。

**按 MN 功能映射我们的优先级**：

| MN 功能 | 我们是否要做 | 说明 |
|---|---|---|
| AI OCR（公式/表格/手写） | **P1 做** | 直接替换 0.7.0「检测公式→只存原图」的妥协：识别出 LaTeX/Markdown 表格写入卡片，原图仍保留作对照 |
| AI 自动出题（挖空） | **P3 做** | 从 excerpt 生成 cloze 卡，进 FSRS 队列；复用现有卡片 schema（question 带 `{{空}}` 标记或新增 card type） |
| AI Hint（回忆提示） | **P3 做** | 回忆模态长按遮挡块给上下文线索而非答案；可用本机小模型 |
| Ask 浮窗（选中即问） | P3 候选 | 文字选区右键加「问 AI」，结果可一键存卡 |
| 标题重写/批量润色 | P3 候选 | 低成本，复用模型通道 |
| 智能 TOC | P4 | 扫描书无目录是真痛点，但需整书扫描+长上下文，等通道稳定 |
| AI 拆书/框架重组 | P4 | 重型，后置 |
| 标题链接 | **不用 AI** | MN 明确用本地字典，我们同样 |

## 三、建议的落地顺序

1. **0.11.0 · 标题链接**：schema v6（`link_aliases`）+ 字典匹配 + 高亮层 + 卡片弹窗。纯本地、无新依赖、直接放大已有卡片库价值。
2. **0.12.0 · 公式 OCR 升级**：模型通道抽象（本机/云端二选一）+ 公式/表格识别写入卡片，关闭 known-limits 中最老的一条限制。
3. **0.13.0 · 留白一期**：页边草稿 + 折叠，右键/长按入口。
4. 之后按模型通道的稳定性再排 AI 出题 / AI Hint / 智能 TOC。

每一步都保持：离线默认可用、单事务写入、备份兼容（新表纳入 export/import 清单）、Vitest + 冒烟脚本覆盖。
