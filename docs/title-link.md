# 标题链接（Title Link）

> 0.11.0 引入 · schema v6 · 对应 MarginNote 3.6.4 的同名能力

## 它解决什么

「这个概念我之前学过，但忘了在哪本书的哪一章。」

传统做法是搜索、翻旧笔记、手动加链接——需要你先意识到自己学过。标题链接把这件事反过来：**你过去的卡片主动在当前页面上浮现**，不需要搜索，也不需要手动建链接。

## 怎么用

1. 在卡片编辑器里给卡片一个**短标题**（问题栏），需要时补充「标题链接别名」：`心肌梗死;MI;myocardial infarction`（分号分隔）。
2. 打开任意文档，点工具栏的「标题链接」开启（偏好写入 `localStorage`，下次保持）。
3. 页面文字层就绪后，命中标题或别名的词会出现**青色下划线 + 浅色底**。
4. 点击高亮：弹出当年那张卡（摘录、笔记、图像、标签、来源），同文档可「跳回原文」，跨文档显示来源页码。
5. 同一关键词对应多张卡时，弹窗顶部以标签切换。
6. 右键高亮还可「复制关键词」或「关闭标题链接」。

默认关闭：卡片库还小时开启只有开销，没有可浮现的旧笔记。建议 200 张卡以上再开。

## 关键词规则

- 来源：卡片标题（`question`）+ 别名（`link_aliases`，分号/中文分号分隔）。
- 每个关键词需为**单行、2–24 字符**、至少含一个文字或数字；长问题句不注册，避免把整段问题当关键词。
- 拉丁关键词忽略大小写，且要求**词边界**（`MI` 不会命中 `SMITH`）；中文按子串匹配。
- 同一关键词跨文档共享一个字典条目，命中时聚合多张卡片。
- 同行内重叠命中保留更长者；每页最多渲染 80 处，控制视觉噪音。

## 实现

| 环节 | 位置 |
|---|---|
| 字典与匹配 | `src/features/pdf/titleLink.ts`（Aho-Corasick，纯本地，无网络/AI） |
| 高亮层 | `PdfPage.tsx` → `.pdf-titlelink-layer`，z-index 3，仅命中条接收指针 |
| 卡片预览 | `src/features/pdf/TitleLinkPopover.tsx` |
| 开关与字典构建 | `PdfWorkspace.tsx`（`buildTitleLinkIndex` 按卡片列表 memo） |
| 数据 | `cards.link_aliases`（schema v6，迁移 `006_title_link.sql`） |

匹配输入直接用已缓存的 `page_ocr` / PDF 文字层行数据——不额外跑 OCR，也不额外读盘。页面文本几 KB、字典数百条，单页匹配在毫秒级。

## 与手动 `card_links` 的区别

- `card_links`：**你主动**把两张卡拉在一起，是显式关系，用于脑图/复习的「相关卡片」。
- 标题链接：**系统自动**把卡片标题当成字典条目，在阅读时反向匹配，是隐式索引，不需要维护。

两者并存，互不影响。

## 已知限制

- 只链接标题与别名，不链接卡片正文（与 MN 一致，避免视觉污染）。
- 扫描页依赖 Apple Vision 的行级识别质量；识别错的字不会命中。
- 垂直/旋转排版的页面，命中条的横向位置可能偏移。
- 命中条会拦截其上的点击（用于弹卡），在文字工具下拖选请从高亮外开始。

## 验收

- Vitest 10 项：关键词规范化、别名去重、长句过滤、中文/拉丁匹配、词边界、多卡聚合、空字典、bbox 换算。
- `node scripts/titlelink-smoke.mjs`（需 dev server）：在真实浏览器中加载模块，验证命中、字典条目数、词边界与高亮条的归一化坐标。
