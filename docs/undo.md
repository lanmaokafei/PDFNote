# 撤销与重做（0.54.0）

## 一条栈，管住四类改动

| 操作 | 撤销（⌘Z） | 重做（⇧⌘Z） |
| --- | --- | --- |
| 大纲行内文字（问题 / 摘录 / 笔记） | 写回旧文本 | 写回新文本 |
| 大纲缩进 / 提升 / 拖拽调整结构 | 按快照写回父节点与排序 | 再写回调整后的结构 |
| PDF 手写笔迹（新增、橡皮擦除） | 删掉这一笔 / 按原点位重建被擦的笔 | 再画一次 / 再删掉 |
| 脑图画布笔迹、手写本笔迹 | 同上 | 同上 |
| 删除卡片 | 从回收站恢复（0.52 已有） | — |
| 新建卡片 | 移入回收站（不弹撤销条） | 从回收站取回，id 不变 |
| 清空画布（删除档） | 把这一批卡片从回收站取回并重排布局 | 再移入回收站 |
| 标签拖拽 / 改标签 | 写回原标签组 | 再写回目标标签组 |

实现分两层：

- `src/features/undo/undoStack.ts`：应用级 LIFO 栈，每条记录自带 `undo` / `redo` 两个函数，
  最多 40 步；**只存在内存里**，重启即清空（避免用旧快照覆盖后来改的数据）。
- 各功能自己把「改了什么」变成可执行动作：
  - 大纲结构用 `orderUndo.ts` 的 `snapshotOrder` / `orderDiff`：改前改后各拍一次快照，
    只把真正变化的行写回 `apply_card_order`，没变化就不占栈；
  - 大纲文字记录旧的三段文本，撤销时 `update_card_content` 写回；
  - 笔迹记录原点位与样式，重做时用新 id 重建，并把新 id 回填给下一次撤销。

## 交互

- `⌘Z`：有可撤销的操作就撤销并提示「已撤销：大纲缩进」；没有就回退到「从回收站恢复刚删的卡片」。
- `⇧⌘Z`：重做。
- 输入框、文本域、`contentEditable` 聚焦时 ⌘Z 交给系统（撤销你正在打的字），不动应用栈。
- 提示条 2.4 秒后自动消失。

## 边界（重要）

- 栈是**会话内**的：关掉应用就没了；重启后请用回收站 / 备份恢复数据。
- 撤销栈不区分画布：切画布后仍能撤销上一张画布的改动，撤销时会写回对应卡片。
- 只覆盖上表这些操作。**目录骨架重建、AI 拆书写入、导入 Anki** 仍不进栈（这些是批量派生数据，
  重放代价大于收益）；其中删除类操作都能在回收站找回。
- 「仅清空脑图（remove）」不动卡片本体、也不进栈——它只移除画布投影，不是数据删除。
- 标签拖拽本身是一次 `set_card_tags` 原子替换（去旧标签 + 加新标签在一个事务里），
  所以撤销只需再写回整组标签。
- 一次操作里如果部分写入失败，栈会丢弃这一步（不会反复卡在同一条坏记录上）。

## 验证

```bash
STEP=outline-edit CARD_COUNT=3 node scripts/mindmap-regression.mjs
STEP=canvas-ink CARD_COUNT=3 node scripts/mindmap-regression.mjs
```

- 大纲：Tab 缩进 → `⌘Z` 回到顶层（深度 0）→ `⇧⌘Z` 再回到 c1 下，后续 Shift+Tab / 拖拽照常。
- 画布笔迹：画一笔 → `⌘Z` 后画布与数据都清零 → `⇧⌘Z` 恢复一笔。
- 单测：`undoStack` 5 项（LIFO、重做顺序、新操作清空重做、上限 40、失败丢弃）、
  `orderUndo` 4 项（快照、差异、无变化、新建/删除不参与）。
